# 变速器（Bridge）— 测试设计与评估协议 v5
> 2026-09-15 | 阿月 | 目标：把"桥"从"伪满分"里救出来，或正式证伪它

## 0. 为什么换任务（旧任务的死因）

旧任务（长文抽一个数）**结构上测不出 Mostik 命题**：
- 答案就是一个整数，**答案文本 = 整个计算结果** → 文字通道无可丢，"隐藏状态更优"无处体现。
- 已观测伪相：`shuffle=1.0`（桥与题目无关也满分）、前端 5/5 直接吐正解、0.5B 的错误是"从多个数里挑错"而非"算不出"。
- 结论：旧任务测的是**选择/注意力**，不是**信息传输**。

## 1. 测试目标（可证伪命题）

| 编号 | 命题 | 判据 |
|---|---|---|
| **P1** | 隐藏状态桥能补足 gap，而**文字接力做不到** | `acc(桥) > acc(文字接力)`，同 sender/receiver/任务 |
| **P2** | 优势随**难度**上升 | 难度扫描下 `acc(桥)-acc(文字)` 单调不降 |
| **P3** | 优势随**接力时机提前**上升（Mostik 核心） | 接力点 k 扫描：桥在早期仍有内容，文字在早期无内容 |
| **P4** | 桥**真的在传内容**，不是 priming | `acc(桥) >> acc(shuffle) ≈ acc(常量前缀) ≈ acc(null)` |

**P4 是否决性的**：只要 `shuffle`/`常量前缀` 追平桥，桥就被证伪为"任务引导器"。

## 2. 任务类型（要"过程 ≫ 答案"）

选型原则：**答案不能从文本里直接抄到**，必须经过内部计算；答案又是短的（1个数），这样"过程长、出口窄"，才逼出通道差异。

**主任务 T1｜多跳检索+运算**（本域升级版）
- 正文给一个人 + 6 个**小数值**属性（10–99）+ 干扰句，打乱语序。
- 问题：`X 的{属性A} 加上 {属性B}[再减去{属性C}] 等于多少？只回答一个数字。`
- 答案 = 计算结果，**不在正文中出现** → 排除"提取即答案"。
- 难度旋钮：**操作数个数** `n_op ∈ {1,2,3}`（1=纯检索，即旧任务；2/3=加运算）。

**对照任务 T2｜链式运算**（纯计算，无检索）
- `从 a 开始，乘以 3，再加 7，再减去 12……` n 步，报最终值。
- 难度旋钮：步数 n。

## 3. 评估矩阵（每个任务、每个难度都跑全）

| 条件 | 作用 | 期望（若 P1–P4 成立） |
|---|---|---|
| `sender_alone` | 上界 | 高 |
| `receiver_alone` | 下界/gap | 低 |
| `q+bridge` | 隐藏状态接力 | 高（≈sender） |
| `text_relay` | 文字接力（sender 先吐字，塞 hint） | 中 |
| **`shuffle`** | 桥但用**别人的状态** | **必须低** |
| **`constant_prefix`** | 可学习常量前缀（不接状态） | **必须低** |
| `null` | 零前缀 | 低 |
| `random_basis` | 随机基 | 低 |

**主指标**：
- `gap = acc(sender) - acc(receiver)`
- `gap_closed = (acc(桥)-acc(receiver)) / gap`
- **`content_dependence = acc(桥) - acc(shuffle)`** ← 新增，这才是"传没传内容"的直接读数。旧的 shuffle=1.0 即此值=0。

**辅指标（几何，测"场"是否塌缩）**：cosine(题间)、PR(有效维度)、CKA、L2；并报告桥输出对状态的依赖度（换状态前缀漂移量）。

**成本指标**：前端生成 token/题（桥应为 0；文字接力为正）；等效算力比。

## 4. 排除捷径（对照清单）

- [ ] `shuffle`：换别人状态 → 掉分（不成立则桥=引导器）
- [ ] `constant_prefix`：纯常量前缀 → 掉分（不成立则桥=模板）
- [ ] **答案留出**：训练未见过的数值/结构 → 排除记忆
- [ ] **格式控制**：确认提升不是"格式对齐"造成（用"只答数字"vs"自然作答"两档比）
- [ ] **基向量奇异值**：basis 是否退化成查表（少数维度主导）
- [ ] **前缀被忽略检验**：换题不换前缀，看答案是否跟着题走

## 5. 分阶段

- **P0（已完成 2026-09-15）**：任务候选 gap 探针。
- **P1**：小规模全对照（含 shuffle / 常量前缀 / 文字接力）跑通，看 `content_dependence`。
- **P2**：难度扫描（证 P2）。
- **P3**：接力时机扫描（证 P3）——需要"部分状态"桥，最贵，最后做。

## 6. P0 实测结论（2026-09-15）

**T1 多跳检索+运算**（正文 6 个小值属性 10–99 + 干扰句；问题=选 n 个属性做 +/-；答案不在正文）：

| 难度 n_op | sender(1.5B, CoT) | receiver(0.5B, CoT) | gap |
|---|---|---|---|
| 1 | 0.88 | 0.62 | +0.25 |
| 2 | 0.62 | 0.12 | **+0.50** |
| 3 | 0.62 | 0.00 | **+0.62** |

✅ **坡存在且随难度单调增**（对上 P2）。答案须计算、不在正文（排除提取捷径）。

**造题/测法的三条硬教训（踩坑记录）**：
1. **禁止 CoT = 杀 sender 能力**：prompt 加"（不要解释）"后 1.5B 从 0.62→0.00；必须放开 CoT（`请逐步推理…最后一行只写 答案=<数字>`）。
2. **操作数不可混量级**：把"入职年份(1998-2015)"当操作数，和小数字相加变 2000+，模型语义上不当数字算 → 全错。
3. **不可混运算符优先级**：`8 + 2 × 4` 生成器按左到右=40、模型按先乘除=16 → 假失败。T2 只留 +/-。

**废弃/降级**：
- 旧任务（长文抽一个数）：**结构性测不出 Mostik 命题**（答案文本=整个结果；`shuffle=1.0` 伪满分）。保留作难度=1 的对照。
- T2 纯链式：坡弱（sender 0.25），暂缓。

**对"接力通道"设定的修正（重要）**：
sender 的"计算" = 它的 **CoT 生成过程**，不是 prefill。故 P1 的桥应接力**生成过程中的状态**：
- `text_relay` = 把 sender 的 CoT **文本**塞给 receiver；
- `hidden_relay(桥)` = 把 sender 生成过程中的**隐藏状态**映成 receiver 前缀；
- 对照 `shuffle / constant_prefix / null` 仍必须掉分。

**新增/保留的 P0 探针脚本**：`tasks_v5.py`(生成器) `gap_probe_v5d.py`(最终坡) `probe_frontend.py`(前端吐字探查) `dbg_v5.py`。
